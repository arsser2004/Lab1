# Лабораторная работа  
## Знакомство с клиент-серверным взаимодействием  

### Цель работы  
Изучение основ клиент-серверного взаимодействия в веб-приложениях, освоение базовых принципов работы с HTTP-протоколом, получение практических навыков создания простого веб-сервера и обработки HTTP-запросов с использованием различных технологических стеков.

### Используемые технологии  
- **Язык программирования:** Python 3.12  
- **Веб-фреймворк:** FastAPI (0.115.11)  
- **ASGI-сервер:** Uvicorn (0.34.0)  
- **Контейнеризация:** Docker + Docker Compose  
- **Тестирование API:** Postman / cURL

### 2. Реализация обработчика запросов  
Добавлен маршрут `GET /info`. Сервер запускается на порту `4200`.  
Пример запроса через cURL:  

"""
curl --location 'http://localhost:4200/info'
"""

### 3. Реализация бизнес-логики
Реализована функция days_until_new_year(), использующая только стандартную библиотеку datetime. Она вычисляет количество дней от текущей даты до 1 января следующего года (с учётом високосных лет).
Ответ сервера возвращается в формате JSON:

   Пример ответа на запрос:
   ```json
   {
    "days_before_new_year": 258
   }
   ```

### 4. Контейнеризация приложения
Создан Dockerfile на основе python:3.12-slim, копирующий код и зависимости, и запускающий Uvicorn.
docker-compose.yml пробрасывает порт 4200 и упрощает запуск одной командой.

### 6. Инструкции по запуску:
Предварительные требования:
Установленный Docker и Docker Compose
Склонируйте репозиторий или скопируйте файлы проекта.
Перейдите в папку проекта.
Выполните сборку образа:

"""
docker build -t days-api .
"""

Запустите контейнер:

"""
docker run -p 4200:4200 days-api
"""

или с помощью Docker Compose:

"""
docker-compose up
"""

Откройте браузер и перейдите по адресу http://localhost:4200/info.


### 7. Ответы на контрольные вопросы
Что такое клиент-серверная архитектура и какие её основные компоненты?
Клиент-серверная архитектура — модель взаимодействия, в которой клиент отправляет запросы, а сервер их обрабатывает и возвращает ответ. Основные компоненты:

Клиент (браузер, мобильное приложение, Postman), инициирующий запросы.

Сервер (веб-сервер, приложение), ожидающий и обрабатывающий запросы.

Сеть (протоколы передачи, например HTTP).

Какие основные методы запросов поддерживает протокол HTTP? Приведите примеры их использования.
Основные методы:

GET — получение данных (например, запрос списка товаров).

POST — создание нового ресурса (регистрация пользователя).

PUT — полное обновление ресурса (изменение профиля).

PATCH — частичное обновление.

DELETE — удаление ресурса.
В данной работе используется GET /info.

Что такое статус-коды в протоколе HTTP? Приведите примеры наиболее часто используемых кодов.
Статус-код — трёхзначное число, показывающее результат обработки запроса.

200 OK — успешный запрос (используется в нашем /info).

201 Created — ресурс создан.

400 Bad Request — некорректный запрос.

404 Not Found — ресурс не найден.

500 Internal Server Error — ошибка сервера.

В чем разница между протоколами HTTP и HTTPS?
HTTPS — расширение HTTP, использующее шифрование (TLS/SSL) для защиты передаваемых данных. HTTP передаёт данные в открытом виде, HTTPS обеспечивает конфиденциальность и целостность.

Что такое заголовки HTTP и для чего они используются?
Заголовки — пары «ключ-значение» в запросе или ответе. Они передают мета-информацию: тип контента (Content-Type: application/json), авторизацию, кеширование, язык и т.д. В нашем ответе автоматически устанавливается Content-Type: application/json.

Что такое контейнеризация и какие преимущества она предоставляет при разработке веб-приложений?
Контейнеризация — упаковка приложения и его зависимостей в изолированное окружение (контейнер). Преимущества:

Одинаковое поведение на разных системах.

Лёгкость развёртывания и масштабирования.

Изоляция процессов.

Упрощение CI/CD.

В чем разница между образами и контейнерами в Docker?
Образ — неизменяемый шаблон (снапшот файловой системы и инструкций), из которого создаются контейнеры. Контейнер — запущенный экземпляр образа с собственным изолированным процессом.

Какие основные типы данных могут передаваться в теле ответа при работе с веб-сервисами?

JSON (наиболее распространён).

XML.

HTML.

Текстовые данные (plain text).

Бинарные данные (изображения, файлы).
В данной работе используется JSON.

Что такое маршрутизация в контексте веб-приложений и как она реализуется?
Маршрутизация — механизм сопоставления URL-пути с конкретным обработчиком (контроллером). В FastAPI она реализуется с помощью декораторов (например, @app.get("/info")), Flask использует @app.route('/info').
